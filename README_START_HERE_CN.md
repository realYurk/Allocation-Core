# Allocation Studio · 可编辑分摊规则设计器

> **这是可配置、可保存、可运行的分摊规则前端，不是只读仪表盘。** 计算核心 Allocation Core 完全保持原样。所有业务金额由独立 Go 可执行程序全量计算；网页不实现金额公式。

## 一、3 步开始（Windows 零基础）

1. 下载完整 ZIP，右键**全部解压**。不要在 ZIP 预览窗口中直接启动脚本。
2. 双击根目录 **`Start_Windows.cmd`**。保持黑色 CMD 窗口打开，浏览器自动弹出。若未自动弹出，手动访问 **http://127.0.0.1:8866/designer**。
3. 页面左上角选择 **「双因子费用分摊」**，单击 **「从示例创建我的规则」**。输入英文项目名，例如 `my_first_fc`，单击创建。现在所有规则字段都能编辑。

原来只读的分摊工作台仍然保留：访问 **http://127.0.0.1:8866/**。两个页面共享同一批项目与独立计算核心。

## 二、在浏览器中亲自做一次 70% + 30% 双因子

在自己的双因子项目里：

1. 左侧选择 **「多步骤分摊」→ 第 1 步**，单击中间 **「② 分摊因子」**。
2. 将 `material` 的比例从 **75** 改为 **70**，将 `revenue` 的比例从 **25** 改为 **30**。比例填的是百分数，不是 0.70 / 0.30。
3. 右侧即时配置检查应显示 **驱动合计 100%**。单击顶部 **「校验草稿」**：这个按钮调用原始 Go 核心的 `doctor`，而不是浏览器假校验。
4. 单击 **「保存规则」**。服务器先检查草稿；未通过就拒绝替换之前的有效规则。
5. 单击 **「保存并运行」**。进入 **「真实计算结果」** 查看输入额、输出额、守恒结果、完整结果 CSV 和压缩证据下载。

注意：一个商品可能因为不同驱动占两行，这是每个因子的贡献明细，而不是重复记账。财务报表如需商品总额，应按维度汇总。

## 三、配置多步骤或分叉合并

| 需求 | 在界面中怎样配置 |
|---|---|
| 两步骤：工厂 → 商品系列 → SKU | 复制「制造业两步分摊」示例；点击左侧第一步和第二步分别修改目标规则、分摊驱动 |
| 一个阶段同时采用多种因子 | 「② 分摊因子」点击 **「添加一个分摊因子」**，选择 Driver、权重字段和百分比 |
| 下一步读取上一步的计算结果 | 在「① 金额来源」里把来源选择为**上一步的步骤名称**，输入份额 100% |
| 75% / 25% 两条路径分别计算 | 从「路径分叉与汇合」示例开始，两条路径都从 `expenses` 取数，份额分别 75% 和 25% |
| 汇合结果 | 选择步骤类型 **「合并上游结果」**，将多个先前步骤设为输入 |
| 只计算某个品牌、地区、期间 | 打开「④ 筛选与守恒」，在对应维度的“包含/排除”中设置成员 |
| 新建科目、成本中心、车型等业务维度 | 左侧「维度设置」添加英文维度编码，再准备对应的 CSV 列 |

**重要：** 如果你改了某一步的名称，下一步引用它的「金额来源」也要同步修改。编辑器会提示未找到的上游名称。每次修改都需要经原 Go 内核验证。

## 四、Total、As Is、Source 到底是什么意思？

| 技术名 | 界面中的业务说法 | 例子 |
|---|---|---|
| `AS_IS` | **来源按此维度分别计算** | 每个工厂独立金额池，不能跨厂混分 |
| `TOTAL` | **来源先按此维度合并** | 旧 SKU 不再区分，先形成待分摊费用池 |
| `SOURCE` | **目标沿用来源值** | 分摊之后仍属于原来的工厂、科目、期间 |
| `ELEMENT` | **目标固定为某个成员** | 输出品牌固定为“品牌甲” |
| `INCLUDE` | **分到指定成员集合** | 目标商品 A、B、C |
| `INCLUDE_EXCLUDE` | **指定范围并排除部分成员** | 包含某系列，排除不允许的商品 |

最常见的组合：**工厂 `As Is` + `Source`**；**商品 `Total` + `Include`**。界面的「③ 维度去向」可以直接选择这些业务语言。

## 五、在前端连接数据并修改原始金额

1. 左侧进入「金额和驱动数据」。在 `expenses`、`material`、`revenue` 等数据集旁点击 **「打开 / 修改 CSV」**。
2. 小规模数据可以直接编辑表格原始 CSV 文本并保存；也能从电脑**导入一份新的 UTF-8 CSV**，登记数据集名称。
3. 新增 Driver 后，返回分摊步骤的「② 分摊因子」，选择新 Driver 的数据集名，并正确填写其**数值字段列名**。
4. 单击「保存规则」「校验草稿」「保存并运行」。每次都从最新的费用和 Driver **全量重算**。

**界面编辑 CSV 限制 1 MB。** 这是前端编辑体验的边界，不是 Allocation Core 的数据规模上限。百万/千万行的正式数据应由 Java、Python、数据库 `COPY`/批量接入或 ETL 生成在企业数据目录中，再通过规则文件连接。

## 六、数据都保存在哪里？

软件目录存放程序和合成示例，**用户数据与软件分离**：

- Windows：`%LOCALAPPDATA%\AllocationStudioData\cases\`
- Linux / macOS：`~/AllocationStudioData/cases/`

每个用户项目拥有独立 `rule.json` 和 CSV；计算结果保存在用户数据目录的 `jobs/` 下，以独立运行 ID 区分。每次计算还会保留当时的 `studio_rule_snapshot.json`，以便后续历史查证。

**内置示例只读；必须先复制为个人项目才能保存修改。** 两个浏览器窗口同时编辑时，过期版本保存会拒绝；运行中的项目也拒绝通过界面修改输入。不要把真实企业数据打进要公开发给其他公司的程序发行 ZIP。

## 七、Linux、macOS 怎么打开？

Linux：

```bash
chmod +x start_linux.sh
./start_linux.sh
```

macOS：

```bash
chmod +x Start_Mac.command
./Start_Mac.command
```

也可以双击 `Start_Mac.command`，但需要按照系统和公司安全制度批准未签名的本地执行程序。

系统自动选择正确的 `studio_<OS>_<CPU>` 前端启动器；它再调用配套、同平台的 `core/alloc_<OS>_<CPU>` 原生 Go 计算程序。不需要额外安装 Go、Python、Node 或 Redis。

## 八、出现报错怎么办？

- **网页无法连接：** 检查启动窗口是否关闭、端口 `8866` 是否已被占用，确认 ZIP 完整解压。
- **保存按钮提示只读：** 当前选的是内置示例，请先创建自己的副本。
- **百分比合计不是 100%：** 先修改因子比例；对于分叉步骤，还要检查上游路径份额。
- **Driver 缺少字段：** 核对 CSV 首行表头与规则中的 `weight_field` 是否完全一致。
- **保存失败：** 右侧黑底日志显示真正的后端错误；旧规则仍保留。
- **守恒不通过/分母为零：** 浏览器不会自行修正金额，必须修正数据或目标匹配后重新完整运行。
- **不能导入千万行 CSV：** 请交给正式 Java/Python/SQL 数据接入，不要尝试在网页文本框处理千万行。

## 九、产品边界

当前这是一款**单机本地规则设计与核验工具**，不是多用户规则发布审批系统。它能配置绝大多数 `allocation-ir/2.0` 内容；对于复杂层级树、精细驱动筛选等，可用「高级 JSON 编辑」继续修改，再调用核心检验。浏览器的结构提示不是实际计算结果；唯一权威来源始终是 Go 计算核心输出的 `results.csv`、`run_summary.json`、`reconciliation.csv` 与压缩 ledger。
