# V15 版本审视与验证边界

## 已实现的增量

1. 同阶段双因子规则（75%/25%），在现有通用 Allocation 内核中计算，预期商品A=725、商品B=275。
2. 同阶段三因子规则（50%/30%/20%），预期商品A=590、商品B=410。
3. 两步骤案例（工厂 → 系列 → 商品）复用，预期商品A=100、B=300、C=400、D=400。
4. 原有 DAG 分叉/合并案例与双因子结果一致，但计算结构不同。
5. `doctor` 检查缺失数据文件、金额表和 Driver 表字段，减少配置错误。
6. `explain` 输出来源连线、因子份额、逐维来源/目标配置和守恒维度。
7. `compare` 逐组生成分摊前后对照 CSV，保留来源和目标粒度差异并增加总计行。
8. 离线规则试算网页：一键切换四个默认场景、调金额和驱动、错误提示、导出完整规则包 ZIP，兼容 Windows 离线打开。
9. 四个 ASCII 命名 Windows BAT 启动脚本，保留日志、每次生成新的输出文件夹。

## 测试及交付验收

- Go `go test ./...` 通过；新增的多因子、前后对照以及数据就绪测试通过。
- 浏览器的四场景试算分别通过。
- **网页下载的四份 ZIP**：均由编译的 Go 引擎再次执行成功，且 `comparison.csv` 总计行差额为零。
- 修改金额至 2000、双因子比例为 70%/30%，导出 ZIP 后由 Go 引擎重新计算通过。
- 比例总和为 80% 时，网页拒绝导出并给出操作提示。
- `results.csv` 的多个因子贡献行需要按商品聚合，未把多行错误认作多商品。

## 未完成及风险

- 不保证单文件 HTML 的完整配置编辑能力覆盖所有 100 步复杂 DAG；复杂规则仍由 JSON/数据接口处理。
- V15 未新增百万级性能基准，不能宣称比 V14 更快。
- 当前 `doctor` 只查字段与文件存在性；零分母和驱动合法性在 `run` 时检查。
- 没有承诺 Windows EXE 已在用户单位计算机上直接测试；需要目标机器验收。
- V15 不做审批、复杂 RBAC、数据库 ACID 事务、任意语言的原生计算代码生成。
