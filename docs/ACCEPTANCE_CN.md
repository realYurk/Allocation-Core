# 可编辑规则设计器验收记录

## 核心边界

**没有修改、重编译或替换 Allocation Core 的任何核心源文件及运行程序。** 本轮仅升级 Studio 本地启动器和内嵌页面。核心交叉 SHA 验证见根目录 `CORE_UNCHANGED_SHA256.json`，最终发行记录见 `RELEASE_SHA256.txt`。

## 已完成实测

- `go test -race ./...`、`go vet ./...`：独立 Studio 源码通过。
- 页面真实交互：复制只读双因子示例 → 比例 75/25 改为 70/30 → Go `doctor` PASS → 保存 → 调用原核心全量运行 PASS。
- 此案例实际结果：输入 1,000.00，输出 1,000.00，1 个金额池 PASS；四条贡献明细金额分别为 560、140、150、150，合计不变。
- 多步骤：复制两阶段案例 → 更名第一步、修正第二步引用 → Go 规则检查/完整计算 PASS，1,200.00 → 1,200.00。
- 修改原始金额 CSV，再全量重算：2,400.00 → 2,400.00，守恒 PASS。
- 保存过期 SHA：409 拒绝；Driver 字段不存在：422 拒绝保存、旧规则 SHA 不变。
- 只读示例非法直接编辑、路径非法项目名：由后端拒绝；本地文件名必须是安全英文 CSV。
- 分摊规则原本支持的分叉汇合、三因子、磁盘、HTTP 等功能仍由未改动核心保留。

## 验收限制

Linux x64 实际运行。浏览器自动化因为当前容器不能直接用 Chromium 导航 localhost，采用浏览器 DOM + 通过 Python HTTP 桥接同一真实本地服务的方式验证交互，脚本报 0 个前端异常；不将其描述为在正式 Windows 浏览器中已现场实测。Windows/ARM/Mac 可执行程序已交叉编译，仍需目标系统验收。

本轮不是性能优化：没有提供新的千万行跑分。浏览器预览最多300条结果，完整结果由 CSV 下载；浏览器数据编辑上限为1 MB。
