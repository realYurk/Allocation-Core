# Allocation Core 组件接入

Core 是 Go 源码模块，不依赖 Studio 和网页。`core` 包是对原有计算引擎的公开入口，和 EXE 使用同一套规则、算法、精度与守恒检查。UI、Windows EXE、Go 组件是不同使用方式，不需要都部署。

## Go 项目直接集成

将完整源码包放在本机，项目安装 Go 1.23 或更高版本。在自己的 Go 项目目录配置本地依赖，例如：

```powershell
go mod edit -require=allocationcore@v0.0.0
go mod edit -replace=allocationcore=C:/local/Allocation-Core
```

将路径替换为源码包实际解压路径。代码示例：

```go
package main

import (
    "fmt"
    "log"
    "allocationcore/core"
)

func main() {
    result, err := core.Run("rules/rule.json", "output/run-001", core.RunOptions{Workers: 2})
    if err != nil { log.Fatal(err) }
    fmt.Println(result.Status, result.InputAmount, result.OutputAmount)
}
```

规则文件和 Driver/金额数据必须符合既有 Core 契约，路径及输出目录由调用方提供。大数据可使用 `core.RunDisk` 及 `RunOptions`。`core.ParseSpec` 和 `core.Validate` 使用现有规则解析器与规划器。调用不启动网页，也不调用 EXE。调用方需要根据操作系统和架构自行编译 Go 程序；源码包不能像 Java JAR 一样无需运行时或编译就直接执行。

目前这是最小的 Go 集成入口，完整业务接口、上下文取消、稳定版本兼容承诺、面向 Java/Python 的 SDK 或动态库尚未提供。Java 等其他语言当前可调用现有 Core 命令行或服务，但这需要部署相应平台的可执行文件；不能声称它们已经支持无 EXE 的直接库调用。生产使用仍需真实规则、Driver、业务对账及目标环境验收。
