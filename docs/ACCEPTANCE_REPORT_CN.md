# Allocation Studio 独立界面 · 当前环境验收报告

## 交付方式与冻结边界

- 保留原 Calculation Core 的全部源码、编译程序及示例，不向 `core/` 写入新代码。
- 使用 SHA-256 对已提供计算核心目录与本发行包内 `core/` **双向逐文件比对**，应当 0 遗漏、0 修改、0 额外文件。
- 新增一个仅本机可访问的 Go 网关，静态网页被打包到启动器内部；系统自带浏览器即可使用，不需要 Node、Python 或 Go 运行环境。
- 软件位于安装目录；用户公司的业务案例及历次结果位于独立用户目录。

新增网关 Go 自动化测试、`go test -race`、`go vet` 通过；客户端脚本经 Node `--check` 通过。Windows x64/ARM64、Linux x64/ARM64、macOS Intel/ARM64 均完成交叉编译。

## 尚待本机/生产环境验收

- Windows、macOS 新 UI 启动器尚未在对应真实设备上运行；本次只在 Linux x64 进行了运行与 HTTP 端到端验证。
- 在当前容器里 Chromium 无法完成无头截图，因此不能宣称视觉像素级的自动化截图验收通过；实际浏览器兼容性与布局需在目标设备上复核。
- 示例和新网关是本机财务检查台，**不是**具备多用户授权、生产级持久调度、内存/磁盘硬隔离的大型门户。
- 默认读取/展示来源最多 500 行、结果最多 300 行；金融对账仍以核心完整标准文件为准，勿用前端样本合计替代全量核验。
- 没有改动、重新压测或声称提升 Core 的千万级吞吐性能。界面不计算金额、不开发第二套分摊公式。
