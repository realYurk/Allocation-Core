# 生产就绪状态与发布门槛

本页记录能力边界，不把合成测试通过视作真实业务验收。状态含义：PASS 为限定范围内有证据；PARTIAL 为能力或证据不完整；BLOCK 为已知条件阻止验收；NOT_TESTED 为尚无对应测试证据。

| 项目 | 状态 | 当前证据与限制 |
| --- | --- | --- |
| 未连接金额来源 | PASS（合成规则） | 已声明金额源必须连接或在 `ignored_amounts` 中明确记录原因；不证明声明之外没有遗漏的业务数据。 |
| 来源筛选未命中 | PARTIAL | 可设置 `source_unmatched_policy: BLOCK`；默认仍允许透传并在摘要报告行数、净额和绝对额。统计是阶段输入，不可跨阶段相加。来源范围是否符合业务仍需独立确认。 |
| 部分目标缺失 | PARTIAL | 可显式配置全局或按来源的必需目标及正权重；不配置时不能证明目标完整。业务成员、层级和有效期须由业务提供。 |
| 输入快照 | PARTIAL | 执行使用逐文件快照并记录捕获字节的哈希。故障测试覆盖复制完成后、复核前源文件变化被阻断；这不是多文件原子快照，也不能证明所有并发改写模式都被识别。调用方应使用冻结的输入版本。 |
| 失败与检查点恢复 | PARTIAL | 合成测试覆盖阶段中断、重放、损坏文件、输入变动和旧格式阻断；进程强杀、断电、磁盘耗尽及目标系统恢复仍需专项测试。 |
| 独立对账 | PARTIAL | 支持完整坐标、分侧重复政策和固定精度；内存取决于最大分区，不是恒定内存。与企业参考结果的对账尚未执行。 |
| 跨语言接入 | PARTIAL | Go 源码 API、Java/Python 进程客户端已提供；后两者需同平台 Core 程序，非同进程原生库。稳定版本与兼容承诺尚未正式建立。 |
| 容量与性能 | PARTIAL | 有百万级合成测量；不同池分布、并发、空间配额和目标硬件的长期容量尚未确立。不能将历史单次测量作为 SLA。 |
| 真实业务投产 | NOT_TESTED | 需要原系统冻结导出、规则和 Driver 定义、逐坐标独立对账，以及目标环境权限、性能和故障恢复验证。 |
| 正式发布治理 | BLOCK | 尚无正式稳定版本标签和许可证决定；持有人需决定授权条款。版本政策、发布工件来源、回滚和支持承诺也须建立并履行。 |

## 发布前的最低检查

1. 使用固定源码提交和 Go 工具链，在隔离环境生成合成数据；执行全量测试、静态检查、关键包 race 检查及 Java/Python 接入测试。将命令、环境、跳过项和结果留存；不能将跳过的 CI 宣称为通过。
2. 对规则、结果、错误码和检查点的兼容变化做评审；检查点兼容标识变更的迁移策略见 [输入说明](INPUT.md)。回滚包和部署包应保留来源、版本与 SHA-256。
3. 检查发布内容只包含允许公开的代码和合成样例。真实规则、明细、凭据、私有报告和输出不得进入仓库或发布包。许可证须由权利人选择，不得默认第三方可复用。
4. 在目标机器以冻结的真实业务输入进行独立逐坐标对账，并分别记录来源范围、目标集合、守恒、规则合法性和发布审批；任一项缺证据不得合并写成业务 PASS。
5. 用贴近目标分布的合成负载和授权环境测试最大池、倾斜、并发、磁盘空间、中断与恢复；记录峰值资源、环境及限制，再确定容量和支持边界。

上述门槛是待完成的工作清单，不代表它们已经执行或批准。
