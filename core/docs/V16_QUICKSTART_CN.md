# V16 零基础使用：财务业务人员与开发人员分别怎么做

## 先理解“分摊”到底是什么

你有一笔费用 1000 元，希望分配给商品。给它一个规则：“75% 按材料用量，25% 按收入”。系统会先把 1000 分成 750 与 250，再分别按各自的驱动比例分配，最后把同一商品的两条结果相加。财务人员最需要看的不是算法，而是**总额对不对、分给谁、为什么、数据来自哪里**。

另一种是多阶段：“工厂费用 1200 → 商品系列 → 四个具体商品”。第一步的输出成为第二步的来源。两者可以混合组合。

## 用 Windows 体验（不需要会编程）

1. 下载 ZIP 并完整解压。
2. 先双击 `00_Windows_Diagnostic.bat`；确认诊断结果正常。
3. 双击 `16_Windows_Run_Trace_Demo.bat`。如果成功，会弹出新文件夹。
4. 用 Excel 打开 `results.csv`：最终商品 A = 725、B = 275（只是虚构案例）。
5. 打开 `reconciliation.csv`：每个金额池都为 `PASS`。
6. 用记事本打开 `first_sku_trace.json`：里面能看到材料路径和收入路径都流向最终商品，并能向上找到费用来源。
7. 再双击 `17_Windows_Two_Stage_Demo.bat`，打开 `comparison.csv` 看分摊前后对比。

CSV 输出带 UTF-8 BOM，Excel 通常能正确打开中文。如果依旧乱码，请在 Excel 中选择「数据 → 自文本/CSV」，使用 UTF-8 导入。此方案不会连接企业数据库。

## 接入新公司的六个动作

1. **业务维度**：期间、费用科目、组织、地区、品牌、商品、币种等，名称与数量都由企业决定。
2. **来源费用**：提供带维度字段和金额字段的 CSV；保留原单据号更容易审计。
3. **驱动数据**：提供按销量、工时、收入或使用次数聚合的 CSV，不必为每个费用科目重复同样的驱动。
4. **规则配置**：从一个有效的规则模板开始，说明哪些维度独立计算、哪些汇总、可以分配给哪些成员、驱动及份额、阶段先后顺序。
5. **试算检查**：先 `doctor`，然后 `run`；打开每组守恒结果和分摊前后对比，再对重点 SKU 使用 `trace` 追溯。
6. **系统对接**：通过命令行/HTTP 从 Java、Python 或其他系统提交规则及输入，并接收结果。业务写回由接入项目负责，不由计算核心猜测数据库结构。

## 三个最容易配错的术语

- **AS_IS**：这个维度来源各成员保持独立金额池，例如每个工厂自己算。
- **TOTAL**：来源先合并这一维度，例如把 SKU 上分散的费用合并成一笔待分配金额。
- **SOURCE**：目标维度不变，例如分摊后仍保留原工厂。配合 `AS_IS` 使用。

要“工厂内部分摊到商品”，一般是工厂 `AS_IS → SOURCE`，商品 `TOTAL → INCLUDE`。不要把所有维度都 TOTAL，守恒维度尤其不能随意改变。

## 代码开发人员需要知道什么

使用发行包根目录的 `go.mod` / `internal` / `cmd`。同一份规则 JSON 可通过 CLI 和 HTTP 运行；Windows 用户使用编译好的 EXE，不需要 Go/Python。`lineage_links.csv`、`ledger.csv`、`source_to_pool.csv` 可以构成向上追溯证据；`trace` 命令按目标行追溯，不会修改结果。

**迁移注意：** V16 血缘引入了来源 ID 命名空间、额外的 `lineage_links.csv`；V16 检查点不能从旧版检查点目录恢复，必须建立新目录。金额算法和既有结果口径保持不变，但下游如果按原旧字符串 `row_id` 关联证据，需要同步适配新的来源标识。
